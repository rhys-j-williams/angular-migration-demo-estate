# Presenter's guide

Everything needed to bring the Meridian Trust Bank estate up, index it, and run the demonstration.

Meridian Trust Bank does not exist. Every customer, account, card, transaction and employee in this
estate is generated by `@meridian/domain-fixtures`, every card number fails the Luhn check and every
account carries the reserved test routing number `021000000`. It is safe to put on a screen.

## Repository shape

The brief describes ten separate repositories. This estate is a **monorepo**: one repository, one
top-level directory per component. The synthetic history, authors, ticket keys and stale branches
are all preserved; what changed is that tags are namespaced, `canopy-ui/v3.7.2` rather than `v3.7.2`,
because the histories share a repository.

## Bringing the estate up

Prerequisites: nvm with Node 14.21.3, 16.20.2 and 18.19.0; Java 11 and 17; Maven 3.9; Python 3.11;
Chrome or Chromium for Karma. Docker is optional — everything has an in-process fallback. Ports are
listed in `PORTS.md` at the repository root and are fixed; do not reassign them.

```bash
mock-external/estate-up.sh      # Verdaccio, the mocks, the services
mock-external/smoke.sh          # end to end check, see below
mock-external/estate-down.sh
```

`estate-up.sh` detects whether Docker is available and falls back to in-process implementations
(embedded ActiveMQ Artemis for IBM MQ, an in-memory Kafka substitute, an in-process Redis) where it
is not. Both modes are supported and both are verified.

`smoke.sh` proves the demo path works: log in through the Keystone mock, fetch retail accounts that
came from the Bedrock mock through the adapter, fire three events for one customer and confirm the
alerts arrive in order, generate a statement PDF and confirm it is non-empty, confirm the Lantern
collector received events, and search the Splunk HEC mock for a correlation id and find it in both
the BFF and the Bedrock adapter.

Run `scripts/verify-estate.sh` for the full acceptance table, and `scripts/verify-traps.sh` to
confirm all forty eight traps are still in place. Run the trap check **before every demonstration**
— an over-helpful session may have fixed something.

## Indexing for the demo

Index in this order; the first two carry the story and take longest:

1. `canopy-ui` — the bottleneck, and the source of seventeen of the traps
2. `retail-web` — the largest surface and the loudest failures
3. `business-web` — the awkward one, two versions behind on everything
4. `keystone-web`, `ledgerline-web`, `iris-widget` — the fan-out
5. `platform-services`, `lantern-sdk`, `mock-external`, `platform-tooling` — context

Before the demonstration, load `KNOWLEDGE.md` as Devin Knowledge notes and both playbooks from
`PLAYBOOKS.md`. Devin quoting the bank's own release train and sign-off rules back at the audience
is a large part of the effect.

## Running the demonstration

The script is `ASK-DEVIN-PROMPTS.md`. In outline:

**Act one, discovery, about fifteen minutes.** Ask Devin what the estate is and how it fits
together, then what breaks on the way from 14 to 18 to 22. Ask how many places override Material
internals. Ask whether anyone has tried before — it finds the abandoned spike branch and the notes
explaining why it was given up. Ask about test coverage, and let the room absorb that the coverage
is thinnest on the compliance-critical services.

**Act two, the work, about thirty minutes.** Run playbook one against `canopy-ui` for the 14 to 15
step. Then run playbook two, the Material migration, and let it stop and ask for human visual
review — that pause is the most valuable thirty seconds of the demonstration. Then launch the five
consumer upgrades in parallel and let the room watch them behave differently from each other.
Finish with Devin Review on one of the migration pull requests.

**Act three, the awkward questions, ten minutes.** How long would this take a team. What can't you
do. What would you do first with one week. The answers are in `ASK-DEVIN-PROMPTS.md`.

## If something goes wrong on the day

- A mock will not start: check `PORTS.md` for a conflict, then `mock-external/logs/`.
- Karma hangs: `CHROME_BIN` is not set, or the no-sandbox launcher flags are missing.
- An `npm ci` fails: Verdaccio is not running, or the wrong Node version is active. Every Angular
  directory has an `.nvmrc`; use it.
- A trap reports MISSING: something fixed it. `git log -p` on the file named in `TRAPS.md`.
- Angular 12, 14 and 15 workspaces pin `@types/node` to `16.18.11` deliberately. Their TypeScript
  cannot parse the newer declarations. Do not "fix" it.
